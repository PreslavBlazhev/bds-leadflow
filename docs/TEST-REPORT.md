## 4. owner:create

`tests/integration/hardening.test.ts` пуска **истинския** `scripts/owner-create.ts` (stdin) срещу временна база:
- създаване → Argon2id хеш; паролата не се появява в stdout/stderr или audit;
- слаба парола и несъвпадение → exit ≠ 0, хешът и сесиите не се променят;
- смяна → старата парола не работи, новата работи, **и двете** предишни сесии са обезсилени (`sessionUser` → null, 0 сесии), потребителят остава един (`owner`), audit `owner.password_change` с броя обезсилени сесии.

**Поправено:** преди смяната (upsert), изтриването на сесиите и одитът бяха три отделни операции. При срив между тях старите сесии можеха да останат валидни. Сега са в една транзакция.

Ограничение: скриптът не пита за старата парола (достъпът до терминала се приема за доказателство за собственост). Скриването на въведените символи в истински TTY е проверено само чрез кода, не автоматично.

## 8. Инцидент: безкраен refresh на локалния сайт (08.10.2026)

**Симптом:** сайтът на http://localhost:3015 се презареждаше непрекъснато и не можеше да се работи с него. Измерено: **361 пълни презареждания за 30 с** на /login, въведеният текст се губеше.

**Механизъм (доказан):** dev сървърът изпращаше на браузъра `{"type":"reloadPage","data":"HMR hash mismatch"}` при всяко зареждане (32 пъти за 5 с). Следваше нов „✓ Compiled“, ново зареждане и нов mismatch. Здрав сървър със същия код не изпраща това съобщение.

**Отхвърлени хипотези (с проверка):**
- записите на worker-а/SQLite в `data/` — в чистото копие същият worker не предизвиква нито един reload за 90 с;
- версията на Node — копието на Node 21.5 също е здраво;
- състоянието на процеса — **рестартът на dev сървъра не помогна**, цикълът се върна веднага;
- грешно разпознат workspace root — няма lockfile в родителските папки;
- единичен `next build` или build + E2E, докато dev работи — не развали здрав сървър.

**Причина:** повредено dev състояние/кеш на Turbopack в папката `.next` на основния проект. След преместване на старата `.next` (само кеш; запазена извън проекта) и стартиране с чиста `.next`: **0 презареждания за 60 с**, 0 „Compiled“ в лога. Точният тригер **не е доказан** — единичен такъв пуск не го възпроизведе.

**Поправка и превенция:**
1. Чиста `.next` (старата е изнесена извън проекта, нищо не е изтрито).
2. `scripts/guard-no-dev.mjs` като `prebuild` / `prestart` и в `scripts/run-e2e.mjs`: ако `.next/dev/lock` сочи към жив `next dev` процес, `npm run build`, `npm run start`, `npm run test:e2e` и `npm run check` **отказват** с обяснение.
