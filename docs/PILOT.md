# Първа реална проба — до 25 бизнеса (Варна, Плевен)

Състояние: **подготвено, не е пускано** (няма ключ; не са правени заявки към Google). Проверено с фалшив API в `tests/integration/pilot.test.ts`.

## Какво е подготвено

| Изискване | Как |
| --- | --- |
| Отделна реална база без демо записи | `npm run real:init` → `%LOCALAPPDATA%\BDS-LeadFlow\real.db` (извън проекта), без seed. Проверява 0 demo записа. Новите дневни списъци са на пауза, докато няма активен източник. |
| Ограничен подбор до 25 | `npm run pilot:discover -- --run --limit=25` (максимум 25). Без `--run` показва само план, без заявки. |
| Сравнение със старата история | Всеки кандидат се сравнява по телефон, сайт и име + град с моите записи (импортирани CSV, DNC, всички статуси). Съвпадение → „В моята история / DNC“ и не може да се одобри. |
| Ръчен преглед преди обаждания | `/pilot`: „Зареди данните“ → преглед → „Одобри за обаждане“ / „Отхвърли“. Одобрение е възможно само след преглед на заредените данни. „Позвъни“ се появява само при одобрените. |
| Видими липсващи данни и източник | При всеки кандидат: „Няма телефон“, „Няма сайт в профила (не доказва, че няма сайт)“, „Няма рейтинг“, статус. Източник: „Google Maps (Places API, зареден на живо, не е записан)“ + връзка към Google Maps. |
| Бюджет в кода | `PLACES_MAX_DETAILS_PER_MONTH` (900) и `PLACES_MAX_SEARCH_PER_MONTH` (2000) в `.env.real`. Броячът (`ApiUsage`) отказва заявката **преди** да е изпратена. |

**Без импортирана стара история не може да се гарантира „никога не съм звънял“.** Страницата и командата го казват изрично.

## Съответствие с условията на Google за ЕИП

- Пази се **само `place_id`** + моите решения (одобрен/отхвърлен/бележка). Име, адрес, телефон, сайт и рейтинг се зареждат на живо и не се записват. Условията изрично забраняват *„copy and save business names, addresses, or user reviews“* и кеширане.
- Карта не се показва (без „With any Map“). Има само връзка към източника в Google Maps.
- След реален разговор: „Създай мой запис“ създава CRM запис с данните, които **бизнесът потвърди в разговора**, с отметка за потвърждение и бележка за произхода. От Google остава само `place_id`. Това е разумно тълкуване, но **не е правна гаранция** — виж „Отворени въпроси“.

## Стъпки

```powershell
cd "C:\Users\The King\Desktop\Sites\15. BDS LeadFlow"
npm run real:init          # веднъж; създава .env.real (ако липсва) и real базата
npm run real:owner         # owner за real базата (отделен от демото)
# по избор, препоръчително: стара история → CSV → (в real режим) Нови клиенти → Импорт CSV
npm run pilot:discover     # план и готовност, без заявки
# след ключа в .env.real и GOOGLE_PLACES_TERMS_CONFIRMED=true, LIVE_DISCOVERY_ENABLED=true:
npm run pilot:discover -- --run --limit=25 --max-details=60
npm run real:dev           # http://localhost:3015 в real режим → /pilot
```

Demo и real не могат да работят едновременно (общата папка `.next`). Спри едното, преди да пуснеш другото.

## Отворени въпроси (непроверени)

1. **Покритие на Google в България:** не е измерено (нужен е ключ). Първата стъпка след ключа е `pilot:discover` с малък лимит.
2. **Разрешената употреба:** условията за ЕИП позволяват *„visualize and manage Places content related to a sales team’s customers or opportunities“*. Дали откриването на нови потенциални клиенти попада тук, не е потвърдено писмено от Google. Препоръка: писмен въпрос до Google Maps Platform support.
3. **Правно основание за обаждания** към бизнес номера (особено ЕТ / физически лица) и правила за директен маркетинг — не е проверено.
4. **Обхват:** Text Search връща до 60 места на заявка. За пълно покритие на Варна (над 60 ресторанта) е нужно разделяне на зони — не е нужно за пробата от 25.
